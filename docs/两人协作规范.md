# 两人协作规范

共同仓库为 https://github.com/qingzhenhongshao169/SalesCare 。当前协作副本独立于财务项目；运行中的原项目继续作为备份和参考。仓库可见性由双方负责人管理，不能假定私有仓库可以存放密钥或客户数据。

## 分支与 AI 开工规则（2026-10-22）

- 当前主分支为 `main`，本次交接分支为 `codex/salescare-update-20261022`。主分支保持稳定，两人分别从约定基线创建自己的任务分支；本次交接合并之前，需要新功能者从本次交接分支开始。
- 每次开工先读根目录 `README.md` 和 `AGENTS.md`，检查 `git status --short --branch`。使用 AI 的开发者需把这些文件交给 AI 阅读，不能仅说“继续开发”。
- 先保存自己的改动，再 fetch 和比较远程变化；通过正常合并解决冲突，不强推、不硬重置、不覆盖整份同事目录。
- 完成后提交清晰差异，PR 写明功能、检查结果、迁移与未完成项，由另一人查看后合并。未经分工协调，不同时修改同一个迁移、共享接口或依赖锁文件。
- 具体模块归属尚未写死；以下“数据处理负责人 / 业务负责人”是协作建议，双方明确任务时再确认。

## 日常协作

1. 两人都从同一个仓库获取代码，各自使用工作分支，例如codex/knowledge-ingestion与codex/reception-workflow。
2. 每次提交围绕一个完整任务，写清功能、接口、验证和限制；通过Pull Request由另一人查看后合并。
3. 数据处理负责人维护连接、抓取、解析与切分；业务负责人维护权限、发布、问答、人工接待与SLA。具体模块归属在源码比较后确认。
4. models.py、迁移、统一文档结构和对接协议先共同确认，避免两边同时改出不兼容结构。
5. 两人各自有本机配置与开发账号。密码、真实企业文件、数据库快照、运行日志、模型权重不进入Git。
6. 两人可共用专用联调库，但分别使用约定账号；日常测试使用隔离测试库。数据库变更由约定负责人执行一次。
7. 对接通过经授权的服务接口或统一结构完成，不能靠直接向现有知识表插入数据绕过租户与审核流程。
8. Git上传/拉取不等于数据库同步或发布。拉取后检查依赖、迁移和配置，再部署对应服务。

第一项合作任务：同事处理一份合成产品文档，保留来源、标题、单位与位置；本系统接收为未发布候选，再完成预览、试问、发布和客户回答核对。不要用真实订单作为第一轮联调样本。
