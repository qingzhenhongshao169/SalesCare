# 官网案例推荐 实施与验收

日期：2026-10-19。状态：源码实现及隔离验收完成，原试点未执行迁移、重启或案例自动发布。

## 已实现的行为

- 在已有知识审核体系上增加案例配置，绑定知识版本、正文摘要与官网来源。资料撤回、过期、变更、停用或越出渠道权限时停止展示。
- 根据会话截至当前消息的明确业务信息匹配服务类型、行业和目标。默认第三条有效业务消息后允许主动推荐；主动问案例可提前；问候、重复文本、无关话题不计业务轮次。
- 默认每次一个案例，可设置最多两个；默认权重为服务35、目标30、行业25、运营优先级10。运营优先级不能绕过相关性与权限条件。
- 增加三条业务消息的主动推荐间隔，同一案例不重复主动推送。拒绝、投诉、请求人工、假设表达和对象不清时保守抑制；人工接管沿用原投递守卫。
- 案例作为本轮聊天回复的结构化卡片，提供事实简介、推荐理由和官网详情链接。案例不作为当前项目价格、预算适配或交期依据。
- 推荐由服务端完成，不新增模型调用，不在聊天时抓官网。已打开页面通过SSE复核旧卡片，权限或来源失效后移除可点击卡片；原始附件仍保留审计，访客删除和保留期清理同时清除附件中的原话证据。

这仍是受控的明确业务信息匹配，不是完整语义多意图或统一需求状态重构。旧profile没有被本轮替换。超过200条历史消息的会话暂时停止新增案例推荐，避免依据不完整历史推断项目；启用候选读取上限为200条。
