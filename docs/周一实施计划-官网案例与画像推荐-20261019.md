# 周一实施计划 官网案例与画像推荐

日期：2026-10-19。执行更新：源码与隔离验收已完成，原试点尚未迁移启用。结果见[实施与验收](官网案例推荐-实施与验收-20261019.md)。以下保留原计划，不能将计划目标视为已完成的实测结果。

今天的目标：整理可核验的标梵历史案例，建立推荐规则和测试基线，并在后续实施中做出“先回答当前问题，再自然给出相关案例”的最小闭环。提高可信度是产品目标，尚无客户效果证据。

## 一 当前基础与改造起点

当前 MVP 已有产品与服务配置、已发布公开知识约束、画像摘要，以及推荐区域。`mvp/service.py` 根据 need 标签交集和可售服务价格筛选 Offer；前端目前主要在咨询摘要旁显示名称、说明和价格。

这不等于已实现历史案例推荐：现有结构缺少案例详情链接、项目行业与目标、推荐时机、推荐理由和会话内去重。不能把案例直接作为“符合预算的产品”处理，也不能将客户的预算用于猜测历史项目价格。

本次画像仅指会话内用户明确提供的业务信息，如行业、服务类型、目标、功能偏好、预算限制和实施阶段；保留原话证据。不推测个人身份、收入或购买力。现有统一状态与多意图重构尚未完成，推荐模块不能把不确定画像当作已确认事实。

官网的转化率、跳出率、营销提升数字若缺少明确口径和适用范围，不进入默认推荐摘要，更不能变成新客户效果承诺。案例来源属于标梵公开自述，不包装成独立第三方认证。

## 四 画像匹配与推荐时机

先做资格过滤，再决定是否展示，最后排序。排序权重不能突破租户、公开范围、渠道、审核、来源有效性等硬约束。

### 默认触发规则

1. 首次问候不主动推荐；优先解答用户当前问题。
2. 从第3条有效用户业务消息起允许主动推荐，可配置为第4条。问候、重复发送、空消息、助手回复不计为业务轮次。
3. 达到轮次门槛还须明确当前服务方向，并有行业、功能或目标中至少一项可支持的匹配依据。信息不足则继续交流，不因轮次到了强推。
4. 用户主动问“有案例吗”“做过类似的吗”，可以提前展示最相关案例；没有对应案例则如实说明，可询问是否愿看能力相近的案例。
5. 用户拒绝推荐、正在投诉、明确只要问题答案或请求人工时，不插入主动推广。人工接管后停止AI自主投递。
6. 一次最多1–2个案例，同一案例默认会话内不重复主动推送；用户主动要求重看可再次提供。项目方向切换后重新筛选，旧结果不自动继承。

### 初始排序建议

在合格候选中，采用可配置的初始权重：服务类型35%、功能/目标30%、行业25%、运营优先级10%。这些是待测试的初值，不是已验证的最优权重。

先要求当前服务类型一致，且存在可解释的功能/目标或行业关联，再使用加权分数排序。缺失字段只记未知，不从预算、公司名或资料内容猜测行业。运营权重只调整相关案例之间的次序，不能把无关案例推到前面。

历史案例通常没有可公开核验的成交价，首版不按预算筛除历史案例。推荐时明确“能力参考”；费用、范围和交期仍需当前需求核算。记录推荐所依据的消息范围和对象，避免旧任务采用后续画像，或生成后用户已切换项目仍投递旧案例。

## 五 聊天中的展示

每条推荐包含：案例名称、1–2句事实简介、与用户需求相关的理由、查看标梵案例详情按钮。封面有可靠来源时再显示；没有封面也能正常使用。

优先作为本轮AI答复的结构化附件显示在聊天中，而不只藏在侧栏。推荐文字基于服务端核验过的案例字段生成，链接由服务端提供，模型不得编造URL。

示例：用户已说明工业设备企业，希望建设面向海外的品牌官网，可自然补充：“您提到希望面向海外展示设备与品牌，这里有一个外贸网站案例可参考：新天激光。它可以帮助您了解我们的相关项目经验；具体范围与费用仍按您的需求评估。”

业务效果仍待未来客户验证；点击案例只表示用户点击，不表示认可、成交或推荐有效。

## 六 推荐与RAG的关系

推荐使用离线整理并审核的结构化案例，不在每轮聊天时抓官网。复用现有检索与回答模型调用，避免新增一次串行模型请求。简单资格过滤与排序由服务端完成。

进入模型上下文的案例内容也属于企业事实证据：须与已发布知识/版本绑定，受当前企业、受众、渠道约束，并参与投递前有效性复核。案例停用、知识撤回、权限改变后，不能继续主动推送失效内容；历史消息保留审计并对来源当前状态作相应处理。

两秒是完整有效答复的目标，测试从用户发送到页面显示可用答案与推荐卡片。FAQ/本地回复与实际模型生成分开统计，不以加载提示、首个token或模拟模型代替。今天先记录加入推荐前后的实际耗时与调用次数；模型通道不健康时保留未达标状态，不宣称普遍两秒。

## 七 今天的测试范围与验收

建立30组自测：10组推荐时机，8组画像匹配与项目切换，6组资料/链接有效性，6组隔离、故障与并发顺序边界。20组用于开发，10组保留；同一对话改写放同组。实施前写好期望推荐集合、不能推荐项、触发轮次及必要说明。

必须覆盖：

- 前两轮不主动推、第3/4轮达到条件才推；主动询问案例可以提前。
- 信息不足、领域无关、拒绝推荐、投诉、人工请求时不硬推。
- 工业外贸网站、建筑设计官网、会员服务小程序分别匹配；网站案例不能冒充做过同类CRM。
- 预算降低、暂定、假设、上限不被当作历史项目报价；不同项目不继承错误预算。
- 刷新、重连、任务重试不重复插入卡片；生成中项目变化或人工接管时抑制失效结果。
- 案例停用、知识撤回、跨租户候选、非公开资料、失效链接不进入可推荐集合。
- 已发历史内容与后续有效性区分；模型错误、无案例和无封面都有可用的回退表现。
- 实际模型与FAQ路径分别记录完整响应时间、成功/失败、推荐附加开销和实际调用数。

今天完成的判定：首批已核对并审核的案例资料可追溯；推荐时机与相关性测试有逐项结果；10组保留场景没有关键越权、错误项目归属和未经依据承诺；聊天卡片与去重流程通过浏览器自测。样本仅证明当前自测范围，不外推真实转化或市场需求。

交付：案例候选清单与审核结果、字段/规则说明、30组测试及结果、最小推荐闭环（如实施完成）、时效报告和未完成项。任何尚未核对的资料、未跑的测试、未通过的模型健康检查单列。
