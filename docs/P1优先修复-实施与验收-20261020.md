# SalesCare 五项P1优先修复实施与验收

日期：2026年10月20日。原标梵8767服务已启用本批修改。本轮执行昨日审查的五项P1，尚未完成今日计划中的全面召回扩展和正式两秒性能验收。

## 已实施

| 项目 | 实际修改与结果 |
|---|---|
| 询问误改方向 | 本轮检索主题与持久化选择分开。先选管理系统，再问官网案例，画像仍为管理系统；明确替换和撤销按用户原话处理。回复的确认、取消与项目重开进入共享任务覆盖检查及回退。 |
| 新旧项目串用 | 新增共享项目边界模块，用于画像、任务规划、回答上下文、追问解析、模型历史和案例上下文。明确重开后不继承旧方向、预算和交期；假设、否定和询问不作为重开命令。历史原话和回复保留。 |
| 上级标题条件丢失 | Markdown可识别连续标题，分块保存完整祖先标题路径及对应块标识，DOCX表格也携带其祖先标题。新构建标识为native-v2及对应分块版本；旧构建清单仍按旧规则核验，不直接改写旧分块。 |
| 公开价格依据错误 | 用完整金额、元/千元/万元换算及同一服务名称校验，拒绝99999支持99、人数或退款充当售价、其他服务价格串用。保存时验证，侧栏展示时按当前授权来源重新验证。旧错误价格可隐藏并正常停用。 |
| 文档新版投递失败 | 外部投递复用文档感知的规范来源扫描，按文档生效版本校验，不再直接把Knowledge行版本与文档版本比较。新引用附内容与构建证据摘要；旧引用仍校验生效版本、规范内容和渠道范围。 |

价格策略有明确边界：现有Offer页面只表示统一人民币数值，缺少条件、计费周期和币种字段，因此条件价、周期价、范围价及外币价暂不允许作为统一公开价发布。可使用“需求评估后报价”，或后续增加有审核依据的结构化价格展示。此策略不能替代完整价格语义和事实冲突裁决。

相关代码集中在server/project_scope.py、turn_plan.py、dialogue_policy.py、requirements.py、model_gateway.py，以及mvp/service.py、document_parser.py、knowledge_provenance.py、knowledge_retrieval.py、offer_evidence.py和channel_messages.py。没有数据库结构迁移，没有前端源码变更，没有增加每轮理解模型调用。

## 验证结果

- 原始18个专项场景中14个先复现失败，再进行修改。
- 最后后端完整回归524项通过，0失败、0错误、0跳过。其中38项为新增P1专项，覆盖自然改写、撤销、假设、新项目、旧画像下一轮纠偏、Markdown与DOCX层级、表格标题条件、价格对象与单位、来源撤回和文档v2投递。
- 前端15项测试通过。未修改前端代码，本批未重新生成前端构建产物。
- 实际隔离数据库及渠道队列验证了文档v1/v2发布与新版投递，另外确认来源撤回、渠道范围排除和内容被改写时继续拦截。没有向真实外部平台发送消息，不作为钉钉、企微或微信平台联调结果。
- 昨日冻结题集v1保留；新增v2将4条“资料或案例询问”预期从selected调整为unknown，明确它们是当前询问主题而非需求选择。测试读取新版本；此项是修正规范与历史预期，不是未见题准确率证明。

最终轮次画像、正文关键边界、案例展示、刷新及页面脚本检查通过；页面脚本错误为0。6轮直接采用模型回答，4轮为fallback_numbers后按本轮任务回退。每轮均调用一次生成模型，没有增加第二次理解或修复模型调用。

## 后续仍需处理

本批只处理有明确证据的P1边界，仍以显式操作和有界历史为基础，不是完整多项目事件账本、语义多意图理解或长期记忆。

RAG仍需继续处理普通查询的漏召回、多任务证据分配、关键词路径重排、原生表格字段回退和无关来源回退。中间验证曾出现管理系统咨询退回宽泛官网报价资料，这属于下一批召回与回退质量问题，不能因画像修正而认为全部回答正确。
