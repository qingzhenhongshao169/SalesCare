# 预算更新未生效：修复与验收

2026-10-15，已部署到原内网 MVP，无数据库结构变更。

## 原因

原预算正则支持「预算改为5000」，不支持「预算可能只有5000元了」等自然表达，因此继续保留旧预算一万元。聊天上下文与摘要分别使用不同正则，导致两端都可能读到旧需求。「希望两周上线」原来也不在摘要的时间识别范围内。

## 修复

- 在 `server/requirements.py` 统一预算和期望时间识别，供 `mvp/service.py` 的会话画像和 `server/dialogue_policy.py` 的回答上下文共同使用。
- 支持 5000元、5k/5K、5千元、五千元，以及「可能只有」「目前暂定」「从一万降到五千」等表达。保留用户原话作为证据，不把暂定预算当作确定报价。
- 新预算覆盖旧预算；用户明确取消预算/时间时移除该项。没有新预算的无关消息保持原值；假设、否定、未说明归属的普通数字和范围不会按单一确定预算覆盖。
- 摘要补充两周、2周、两周内上线等明确期望时间，仍属于客户期望。
- 回答核验在后续追问中也检查旧预算，不只检查预算更正当轮。模型沿用旧数值时回退为按最新需求组织的回答。
- 「确认5000元、两周一定能做完」仍按报价/交付核算边界处理，不作保证。分阶段需求可引导先梳理首期内容与后续扩展。
- 用只读预览后执行的定向修复工具，对截图对应的一条未关闭标梵会话按访客消息顺序重建预算和期望时间字段，记录审计；未改写已发出的历史消息、企业知识、账号或模型密钥。

## 验收

- 后端全套 **352 项通过**，其中新增 27 项参数化/集成检查。覆盖自然预算表达、k单位数值核验、否定/假设/范围、取消、销售与通用客服画像、旧预算模型输出拦截。
- 真实 Chrome 通过内网页面完成三轮：一万元/两周 → 可能只有5000元 → 要求保证5000元两周做完。第二轮起摘要为 `¥5,000`，期望上线为「两周」，回答使用5000而不是1万；最后一轮保留费用/排期核算边界。页面脚本错误 0。
- [浏览器原始记录](budget-update-live-check.json)、[页面截图](budget-update-live.png)。本次验证可走原有降级路径，不声称真实大模型生成恢复或速度提升。
- 既有会话修复后再次只读预览，命中原会话和合成验收会话，待修复数量为 0；原 API、AI/SLA、渠道及知识处理健康检查通过。

刷新当前咨询页面可以看到更正后的摘要。历史消息保留当时真实内容；新的回答使用修正后的解析逻辑。

## 复现和边界

- `mvp/tests/test_requirement_updates.py` 为回归检查。
- `scripts/verify_budget_update.cjs` 用公开访客入口产生合成咨询，无员工登录密码；使用已有 Playwright/Chrome，参数与响应速度验收相同。
- `scripts/repair_requirement_profiles.py` 默认只预览，必须指定企业、匹配原话和最近时间窗，只有 `--apply` 才更新匹配的未关闭会话的两个需求字段。不调用模型、不删除原消息、不改企业报价。
- 当前仍是有边界的规则识别；复杂含糊表达、区间预算和未明确归属的裸数字需要进一步澄清，不推断为确定预算。没有声称所有中文金额表达均能识别。
