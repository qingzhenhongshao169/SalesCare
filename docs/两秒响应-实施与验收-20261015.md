# 两秒响应优化：实施与验收

日期：2026-10-15。运行入口：http://192.168.0.236:8767/ 。

## 结论

本轮已在现有内网 MVP 上部署：任务提交即时唤醒、验证后消息即时推送与断线续接、已审核标准 FAQ 快答、企业隔离的模型连接复用。未更换技术栈、公司账号、密钥或现有模型。

标梵现网 12 个问候及标准问题，浏览器从发送到显示回答实测 69–154ms。一般生成问题尚不能承诺两秒：真实供应商生成接口在本轮诊断中仍超时。连接成功或模型列表可读取，并不代表生成服务正常。本轮解决了系统自身不必要的等待，没有把供应商故障包装为模型恢复。

## 具体改动

1. **任务调度**：PostgreSQL 在事务提交后通知 Worker，提交失败不会唤醒不存在的任务；租约、同会话先后顺序、并发配额与一秒补扫保留。维护任务限频，避免每次消息通知都重复运行 SLA 扫描。
2. **消息到页面**：API 进程共享数据库通知监听器，消息入库后推送；不为每位访客新建数据库监听连接。浏览器携带原鉴权令牌、按消息序号续接、去重和重连；长开页面持续接收，断线保留轮询补偿。推送的仍是完成知识及权限核验后的答案，不是未验证模型 token。
3. **标准问答**：新增「对客标准快答」配置，管理员/知识发布者可以设置完整问题及对客答案，确认审核后启用。精确匹配才快答；预算变更、代词追问和组合咨询仍走正常检索/生成。每次复核企业、渠道、发布状态、版本、内容摘要及有效期，撤回或内容变化即失效；重复匹配多个有效答案时不随意选一个。
4. **标梵已有资料**：为十条内容未变、已审核发布、低风险的公开知识启用原文快答，沿用其已有审核依据并留审计。没有为企业凭空编写价格、库存或交付承诺。修改对客答案仍需后台审核。
5. **模型连接**：使用有上限、有过期回收的连接池，按企业及服务端点隔离，不共享默认认证头或 Cookie；保留单请求超时与模型回答核验。
6. **故障边界**：保留前一轮八秒客户模型读取等待上限、连续故障后的短暂冷却；此上限不是严格八秒全链路截止时间。检索、排队与故障提示另计；未静默更换模型或复用其他企业密钥。

## 与旧版比较的边界

参考协作仓库旧基线 `968320a` 的模型网关，DeepSeek 业务请求已经禁用深度思考，本轮不能将此作为新优化收益。历史正常调用样本的模型处理曾约 1–2 秒，但它与今天的供应商故障不是同条件对照；没有把历史成功样本和今天 FAQ 命中混成一个提速百分比。无需回滚已实现的知识版本、撤回核验及多租户隔离。

## 尚存问题与后续

1. **供应商生成仍超时**：需要供应商恢复，或企业在自己后台配置可用通道后再验证。当前同账号另一模型的小请求也未证明可用，因此没有自动切换。正常生成问题的真实 P50/P95 尚待恢复后补测。
2. **覆盖率**：十条标准资料不是所有问法的通用缓存。通过知识运营持续整理高频问题并审核；个性化推荐、活动冲突和实时订单不可直接套用 FAQ。
3. **规模**：此次 202 条串行回放不能证明高并发容量。通知失效仍有两秒消息补查及一秒任务补扫；需结合目标并发补充压测与监控。
4. **检索**：现有逐条资料扫描未改为大型向量索引；当前十几毫秒检索不是此次约二十秒超时的主因。
5. **未实施项**：独立备用供应商配置、未验证 token 流式、激进裁剪上下文未本轮上线。先保持事实准确与原工作流，模型可用后再做同题集效果与速度对照。

## 复现入口

- `scripts/run_speed_qa.py`：只使用隔离测试配置与合成企业，可运行 prepare/provider/api/worker；固定 8768、8772 端口，请先检查端口空闲，不用于公司正式实例。
- `scripts/verify_response_speed.cjs`：通过本机 Playwright 与 Chrome 运行 202 条回放；`SALESCARE_QA_NODE_MODULES` 指向安装了 Playwright 的目录，`SALESCARE_QA_BROWSER` 指向浏览器。
- `scripts/verify_speed_live.cjs`：向内网标梵发送十二个公开标准问题，会产生真实测试咨询记录，不修改员工账号或配置。
- `scripts/summarize_response_speed.py`：指定配置、报告及企业，将浏览器开始时间之后的 Usage 与 AIJob 核对。运行期间不要混入其他同企业测试，以免统计混杂。
- `scripts/enable_reviewed_fast_faqs.py`：默认只预览；`--apply` 对符合严格白名单条件的原有标梵资料启用原文快答，跳过已有配置及修改过的资料。
