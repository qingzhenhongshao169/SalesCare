# 周三数据分析1—4：实施与验收

2026-10-21。已在原 SalesCare 8767 服务启用“数据分析”入口，保留现有接待总览、知识、咨询与前端样式。本批未涉及财务工程、Onyx、Linux或磁盘清理，未提交或推送 Git。

## 交付

1. **口径与数据基础**：按会话创建时间形成队列；日期、渠道、业务/测试/未知/全部筛选；明确测试审计可识别历史测试，其他历史不猜测。管理员可逐场标记并留审计。隔离QA环境新会话默认显式标为测试。
2. **服务效果总览**：AI业务接待量、确认独立解决量、真实人工回复量、待核查线索；日趋势及已结束AI参与接待的互斥结果分布（独立解决、人工介入、核查未解决、未知）。卡片可下钻，图表与明细共用同一数据集合。
3. **主题气泡图**：可切换全部咨询主题与待复盘主题，按去重会话数映射气泡面积；支持键盘、悬浮详情和点击下钻。最多12组，溢出合并时仍去重。精确数量配排行，手机显示可点击排行。
4. **优化待办**：重复说明、更正或需求变化、回答回退、资料不足线索、客户仍需帮助；支持待核查/已核查/待补知识状态与原会话回看，管理员可进入原知识库补充。不会自动认定错误、修改价格或发布新知识。

补充最小闭环：客户可对单条业务回答选择“已解决此问题/仍需帮助”，可再次点击撤回。问题级反馈独立统计，不自动计整场解决。员工核查整场解决必须选择本会话依据并明确确认所有当前需求；有人工介入不计AI独立解决；新业务问题使旧解决结论失效。旧序列核查请求返回409，防止据旧消息改结论。

## 实现边界

- 新增 `analytics_records`、`answer_feedback` 两张附加表和 `0013_customer_analytics` 迁移，保留原聊天与知识数据；两张表均启用并强制租户RLS。
- 分析接口 `/api/analytics`，员工核查接口 `/api/analytics/conversations/{cid}`，访客问题反馈接口在原公共会话路径内。沿用角色、CSRF、访客归属和租户权限。
- 分析在读取侧按本地可审查规则生成，未在聊天热路径添加理解/反思LLM调用。QA默认测试标记仅在隔离test模式生效。
- 删除咨询会清除相关反馈及核查投影，已删除原文不再生成主题或线索。核查列表不输出明文联系电话或邮箱。
- 最多分析筛选范围内最近2000场；超限明确提示，coverage为全筛选范围的分类数量，卡片/图表/明细仅代表这一有界样本。未声称大规模分析性能已验收。
- 日期输入采用浏览器时区，日趋势采用企业时区，口径说明中明确显示。日趋势为最近14个有记录日期，不用补零点伪造数据连续性。
- 主题为本地规则分类，尚非通用语义聚类；复盘状态不是“已修复”。实际费用、满意度和浏览器完整回答两秒达标率不在本批交付范围。
